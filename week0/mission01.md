HTML 정의
1. HyperText Markup Language의 약자, 즉 웹페이지의 콘텐츠와 구조를 정의하는 마크업 언어라는 뜻
2. HTML은 이러한 요소들이 무엇이고, 어떤 의미와 구조를 가지는지 정의하는 역할

분해로 해석
HyperText : 하이퍼링크를 통해 다른 문서나 웹페이지로 이동할 수 있는 텍스트
Markup Language : 태그 등을 활용하여 문서의 구조와 의미를 표현하는 언어

1. HTML은 프로그래밍 언어가 아니라 마크업 언어!

실제 웹페이지 구성 시

HTML : 웹페이지의 구조와 콘텐츠 정의
CSS : 요소의 스타일과 레이아웃 지정
JavaScript : 동작과 상호작용 구현

HTML의 Element와 Attribute는 무엇일까요?

Element : 요소라는 뜻으로, 일반적으로 다음의 형식을 지닌다.

"시작 태그" "내용" "종료 태그"

예시 : <p>Hello HTML!</p>

종료태그는 경우에 따라서는 필요가 없기도 한다.

또한 다음 예시처럼, 요소는 중첩되기도 한다.
<div>
  <h2>상품 가격</h2>
  <p>30,000원</p>
</div>

이렇게 되면, 부모 요소가 div, 자식 요소가 h2와 p가 된다.

Attribute : Element의 요소가 된다. 
<img src="product.png" alt="흰색 반팔 티셔츠" />

여기에서 src와 alt가 속성애 해당한다.

자주 사용하는 속성

id : 요소를 식별하기 위한 고유한 값
class : 요소를 그룹화하거나 스타일을 적용할 때 사용
src : 이미지 등 리소스의 경로
href : 링크가 이동할 주소
alt : 이미지의 내용을 전달하는 대체 텍스트
title : 요소에 대한 추가 정보
style : 요소에 직접 CSS 스타일 적용

특히 id는 한 문서에서 고유하게 지정하며, class는 여러 요소에 같은 값을 사용한다.

2. div와 Semantic Tag의 차이는?

시맨틱은 의미론적인, 의미를 가지는이라는 뜻이다. 즉 태그의 이름과 역할을 통해 콘텐츠가 어떠한 의미를 가지는지 표현할 수 있다.

div 태그 만으로 나쁜 것은 아니지만, div 태그만을 사용할 경우 다음과 같은 단점이 생긴다.

  1) 각 영역의 역할을 파악하기가 어려워진다. 즉 가독성과 유지보수성이 하락한다.

  2) 검색엔진 최적화에 불리하며, 웹 접근성 측면에서도 한계가 있다.

  3) 시맨틱 태그를 적절히 사용하면, 코드 영역의 역할을 알 수 있으며, 스크린리더와 같은 보조 기술을 통해 웹페이지의 구조를 이해할 수 있다.

대표적인 시맨틱 태그
header : 페이지 또는 특정 영역의 머리말
nav : 주요 탐색 링크 영역
main : 페이지의 중심 콘텐츠
section : 주제별 콘텐츠 구획
article : 독립적으로 구성되는 콘텐츠
aside : 주요 콘텐츠와 간접적으로 관련된 내용
footer : 페이지 또는 특정 영역의 바닥글

다만 시맨틱 태그를 많이 사용한다고 좋은 것이 아니다. 각 요소의 목족과 의미에 맞는 태그 사용이 종요하다.

3. <article> vs <section>  두 태그의 차이점은 무엇인가요?

article 과 section 둘 다 시맨틱 태그이지만, 차이는 콘텐츠의 독립성과 목적에서 나타난다.

  -article 섹션

  그 자체만으로 독립적이고 완전히 자립적인 콘텐츠를 감쌀 때 사용한다. 이 페이지만 따로 떼어내서 다른 곳에 복사하거나 공요해도, 내용이 온전히 이해되어야 한다.

  예시 : 문서, 페이지, 애플리케이션, 또는 사이트 안에서 독립적으로 구분해 배포하거나 재사용할 수 있는 구획이 있는 게시판과 블로그 글, 매거진이나 뉴스

  -section 섹션
  주제별로 연관된 내용을 그룹화하여 나누는 영역이다. HTML 문서의 독립적인 구획을 나타내며, 더 적합한 의미를 가진 요소가 없을 때 사용한다.

  예시 : 웹사이트의 '소개(About)', '서비스 목록', '연락처(Contact)' 섹션

둘의 포함관계를 생각하면, 서로의 내부에 들어가서 종속되는 경우도 가능하다.

추가 : 자주 사용하는 추가 태그

텍스트 콘텐츠

<blockquote>	안쪽의 텍스트가 긴 인용문, 주로 들여쓰기, 속성 : cite, 출처 텍스트는 <cite> : 요소로 제공

<dd>	설명 목록(<dl>)에서 선행 용어(<dt>)에 대한 설명, 정의 또는 값을 제공

<div>	유동 콘텐츠의 일반 컨테이너, CSS를 사용하여 어떤 식으로든 스타일을 지정할 때까지 콘텐츠나 레이아웃에 영향을 미치지 않음

<dl>	설명 목록, <dl>은 <dt>로 표기한 용어와 <dd> 요소로 표기한 설명 그룹의 목록을 감싸서 설명 목록을 생성. 주로 용어사전 구현이나 메타데이터(키-값 쌍 목록)를 표시할 때 사용

<dt>	설명 혹은 정의 리스트에서 용어를 표현 

<dl> 요소 안에 위치, 보통 <dd> 요소가 뒤따르지만, 여러 개의 <dt> 요소를 연속해 배치하면 바로 다음 <dd> 요소로 한꺼번에 서술 가능

<figcaption>	부모 <figure> 요소가 포함하는 다른 콘텐츠에 대한 설명 혹은 범례를 표현

<figure>	독립적인 콘텐츠를 표현, <figcaption> 요소를 사용해 설명을 붙일 수 있습니다. 피규어, 설명, 콘텐츠는 하나의 단위로 참조

<hr>	이야기 장면 전환, 구획 내 주제 변경 등, 문단 레벨 요소에서 주제의 분리를 표현

<li>	목록의 항목을 표현 반드시 정렬 목록(<ol>), 비정렬 목록 (<ul>), 혹은 메뉴(<menu>) 안에 위치, 메뉴와 비정렬 목록에서는 보통 불릿으로 항목을 나타내고 정렬 목록에서는 숫자나 문자를 사용한 오름차순 카운터로 표현

<menu>	사용자가 수행하거나 하는 명령 묶음, 이것은 스크린 위에 나오는 목록 메뉴와 눌려진 버튼 아래에 나오는 것과 같은 맥락 메뉴를 포함

<ol>	정렬된 목록을 나타내며, 보통 숫자 목록으로 표현

<p>	하나의 문단을 표현 시각적인 매체에서, 문단은 보통 인접 블록과의 여백과 첫 줄의 들여쓰기로 구분하지만, HTML에서 문단은 이미지나 입력 폼 등 서로 관련있는 콘텐츠 무엇이든 가능

<pre>	미리 서식을 지정한 텍스트를 나타내며, HTML에 작성한 내용 그대로 표현, 텍스트는 보통 고정폭 글꼴을 사용해 렌더링하고, 요소 내 공백문자를 그대로 유지

<ul>	정렬되지 않은 목록을 표현하며 보통 불릿으로 표현합니다.
